## 重構目標

將read_alarm和read_program_block的GIOP協議細節從M70Connection層移至M70GIOP層，
使架構更符合C版本的分層設計。

## 重構內容

### 1. M70GIOP類新增方法

#### mel_get_current_alarm_msg()
```python
@staticmethod
def mel_get_current_alarm_msg(conn: M70Connection, system_no: int, 
                               msg_count: int, msg_type: int) -> Tuple[int, Optional[bytes]]
```

**對應C函數**: `melGetCurrentAlarmMsg(conn, system_no, msg_count, msg_type, msg)`

**功能**:
- 構建GIOP請求（op字段32字節）✓
- 發送mochaGetCurrentAlarmMsgFirst請求
- 接收alarm_string結構響應
- 返回(error_code, alarm_data)

**關鍵修正**:
- op字段大小: 16字節 → 32字節 ✓
- 參數類型: uint32 (使用'<I') ✓

#### mel_get_current_prg_block()
```python
@staticmethod
def mel_get_current_prg_block(conn: M70Connection, system_no: int, 
                               row_count: int) -> Tuple[int, Optional[bytes]]
```

**對應C函數**: `melGetCurrentPrgBlock(conn, system_no, row_count, msg)`

**功能**:
- 構建GIOP請求（op字段32字節）✓
- 發送mochaGetCurrentPrgBlockFirst請求
- 接收prog_block結構響應
- 返回(error_code, prog_block_data)

**已有正確實現**:
- op字段大小: 32字節 ✓
- 參數類型: uint32 ✓
- 響應解析: 直接讀取結構 ✓

### 2. M70Connection方法重構

#### read_alarm() - 簡化實現

**之前** (73行):
```python
def read_alarm(self, ...):
    # 構建GIOP header
    giop_header = M70GIOP.build_giop_header(self)
    request_header = M70GIOP.build_request_header(self, ...)
    
    # 構建packet (op字段16字節 - 錯誤!)
    op_field = bytearray(16)  # ❌
    ...
    
    # 發送和接收
    M70Socket.send_data(...)
    error_code, remaining_length = M70GIOP.receive_response(self)
    
    # 解析響應
    header = M70Socket.recv_data(self._socket_obj, 12)
    ...
```

**之後** (41行):
```python
def read_alarm(self, ...):
    # 調用GIOP層方法 (op字段32字節 - 正確!)
    error_code, alarm_data = M70GIOP.mel_get_current_alarm_msg(
        self, system_no, msg_count, int(alarm_type))
    
    if error_code != 0 or not alarm_data:
        return M70ErrorCode.FAILED, []
    
    # 解析alarm結構
    if len(alarm_data) >= 12:
        header = alarm_data[:12]
        u1, resp_data_type, data_length = struct.unpack('<III', header)
        ...
```

**改進**:
- 代碼行數: 73 → 41 (減少44%)
- op字段修正: 16 → 32字節 ✓
- 層次分離更清晰
- 錯誤處理更簡潔

## 架構對比

### 重構前
```
M70Connection.read_alarm()
  ├─ 構建GIOP header (內部實現)
  ├─ 構建request header (內部實現)
  ├─ 構建data packet (內部實現)
  ├─ 發送請求 (內部實現)
  ├─ 接收響應 (調用M70GIOP.receive_response)
  └─ 解析數據 (內部實現)
  
  問題: op字段大小錯誤(16字節)
```

### 重構後
```
M70Connection.read_alarm()
  ├─ 調用M70GIOP.mel_get_current_alarm_msg()
  │   ├─ 構建GIOP header
  │   ├─ 構建request header  
  │   ├─ 構建data packet (op字段32字節 ✓)
  │   ├─ 發送請求
  │   ├─ 接收響應
  │   └─ 返回原始數據
  └─ 解析alarm結構
  
  優點: 分層清晰，與C版本一致
```

### 與C版本對比

**C版本架構**:
```c

            ├─ socket_send_data()
```

**Python版本架構** (重構後):
```python

            ├─ M70GIOP.build_giop_header()

            ├─ M70Socket.send_data()
```

## 架構優勢

### 1. 職責分離清晰
- **GIOP層**: 負責協議細節（packet構建、發送接收）
- **Connection層**: 負責業務邏輯（數據解析、類型轉換）

### 2. 代碼復用性
- GIOP方法可被其他地方調用
- 協議邏輯集中管理

### 3. 易於維護
- 修改協議細節只需改GIOP層
- 業務邏輯與協議解耦

### 4. 與C版本對應
- 架構完全一致
- 便於參考C代碼
- 便於實現其他mel*函數
